Next, on your machine:

$npx easel-canvas@latest --demo

It opens where you already work.

No new app to switch to. One command adds Easel’s MCP server to the agents you have, and the canvas is a page on 127.0.0.1 that can sit beside the conversation.

$npx easel-canvas connect

Claude Code

In the Claude desktop app’s Code tab, the canvas can sit in the app’s Browser pane, beside the conversation.

  1. npx easel-canvas connect writes Easel into .mcp.json. The app asks you to approve the project’s server once.
  2. Add the canvas to .claude/launch.json and ask Claude to open it.
From the run above (Claude Code 2.1.295, run from a terminal; the Code tab runs the same Claude Code):
claim_board empty-day.html → empty-day.html
write_board empty-day.html
check_tokens: 0 issues

Codex

The same command adds Easel to Codex’s own config, so Codex gets the same tools.

  1. npx easel-canvas connect appends [mcp_servers.easel] to ~/.codex/config.toml, when Codex is installed.
  2. Keep the canvas running and restart Codex.
From the run above (Codex CLI, codex exec):
claim_board empty-day.html → empty-day-codex.html · fork
write_board empty-day-codex.html
screenshot empty-day-codex.html

Cursor

The same command adds Easel to the project’s Cursor config.

  1. npx easel-canvas connect writes .cursor/mcp.json, when Cursor is on your machine.
  2. Keep the canvas running and restart Cursor.
From the run above (Cursor’s agent CLI):
claim_board empty-day.html → empty-day-cursor.html · fork
write_board empty-day-cursor.html
add_comment on empty-day-cursor.html

Gemini CLI too: connect writes .gemini/settings.json. Pick agents with --agents, or see what it would write with --dry-run. Inside Easel, the AI tab can also start Claude Code, Codex, Cursor Agent or Gemini CLI for you.
