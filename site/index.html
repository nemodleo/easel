Why now

The agents moved into the repo. The design didn’t.

  1. 1

    Coding agents already write the UI. They change real files in your repo, every day.

  2. 2

    The design still lives somewhere else: a design file, a chat artifact, a hosted tool. The agent works from a copy.

  3. 3

    Easel puts the design where the agents work: HTML files in your repo, on a canvas you both edit.

Agents work as teammates

Ask Claude Code, Codex, Cursor Agent or Gemini CLI from the canvas, with your selection as context. The board redraws as the agent writes, and the whole run undoes in one step. A Claude Code run’s permission requests come up as cards you answer there.

Many agents, no overwrites

One writer per board. A second agent on a busy board is given a fork next to it, and every change carries a tag with who made it.

How it works

Files, then the canvas, then your agent.

  1. 1

    Files

    Each screens/*.html file is one board. Positions, notes and comments sit next to them in small JSON files that merge with git.

  2. 2

    Canvas

    npx easel-canvas

    Opens ./docs/design on 127.0.0.1. Only the part of the file you change is rewritten.

  3. 3

    Agent

    npx easel-canvas connect

    Adds Easel’s MCP server to Claude Code, Cursor, Gemini CLI and Codex. The in-app chat needs no setup for Claude Code.

Inside the apps you already use

Not one more window. The canvas comes to your agent.

Inside the Claude desktop app

The Code tab runs Claude Code in your project, so the server connect writes gives that session Easel’s tools: it lists boards, reads your selection, checks tokens and leaves comments. The canvas can sit in the app’s Browser pane, beside the conversation.

  1. 1

    In your project. The app asks you to approve the project’s server once.

    npx easel-canvas connect
  2. 2

    Add the canvas as a preview server in .claude/launch.json, then ask Claude to open it.

    { "name": "easel", "runtimeExecutable": "npx",
  "runtimeArgs": ["-y", "easel-canvas", "--port", "4317", "--no-open"],
  "port": 4317 }
